v0.19.0
===

The codename for LÖVR v0.19.0 is TBD.  It is currently <font style="color: red; font-weight: bold;">
not released</font>.

The main highlights of v0.19.0 are:

- Raytracing
- Upgraded SteamAudio Spatializer
- Animated Controller Models
- Luau Support
- New Vector API
- HDR Display Output
- Coroutine-based Task System
- New Error Screen

Raytracing
---

LÖVR supports ray tracing now!  Ray tracing is used to perform intersection tests in shaders, and is
useful for effects like shadows and ambient occlusion.

There is a new `Raytracer` object that holds all the ray tracing data for `Mesh` and `Model`
objects.  Dynamic geometry and animated models are supported.  Most Vulkan GPUs support the
necessary extensions, including Quest 3.

Spatial Audio
---

SteamAudio was previously available as a LÖVR spatializer, but it wasn't included by default because
it was closed source and had a huge file size.  However, SteamAudio was recently open sourced,
allowing it to be shipped with LÖVR by default now!  Additionally, LÖVR upgraded to the latest
version of SteamAudio and the rest of the audio module got some substantial improvements.

### AudioMesh

There is a new `AudioMesh` object, replacing `lovr.audio.setGeometry`.  `AudioMesh` objects are used
to compute realtime reverb as well as audio occlusion, allowing walls and other objects to block
sound.

They can be created from a table of vertices, a `Mesh`, or a `ModelData` and placed in 3D space.
Unlike `lovr.audio.setGeometry`, it is possible to set `AudioMaterial` for each individual triangle
of an `AudioMesh`, create cheap copies of the mesh, and reposition it at runtime.

### Improved Reverb

Reverb is one of the most expensive parts of SteamAudio, so it's important to have control over the
accuracy/performance tradeoff.  There are many new conf.lua options to configure the type of reverb,
the max number of rays and bounces used during ray tracing, and the max duration of the reverb tail.
LÖVR also computes reverb on a background thread, allows choosing between per-source and
listener-centric reverb, and supports changing the reverb volume for each `Source` independently.

### Ambisonic Playback

LÖVR has supported importing ambisonic sounds for a while, but awkwardly wasn't able to play them.
In this version it's now possible to create sources from ambisonic sounds.  These 3D soundfields
support rotation, binaural spatialization, reverb, and all of the other effects supported by regular
sources.

### Binaural Spatialization

There's a new `lovr.audio.setHRTF` function that allows specifying a custom SOFA file to use for
binaural audio spatialization.

Binaural audio spatialization is now a continuous value between 0 and 1 instead of a boolean.  This
makes it possible to smoothly transition between stereo audio and binaurally spatialized audio,
useful for objects close to the listener.

### Miscellaneous

- LÖVR double buffers changes to sources and commits them once per frame by default, so it is
  possible to atomically play several sources at once or modify their parameters.
- There's a new `AudioStream` object, replacing the awkward "stream" mode for Sounds.
- The Oculus Spatializer and the simple spatializer were removed, so projects don't need to worry
  about which spatializer is active anymore -- it's just always SteamAudio.
- It is no longer necessary to create an audio stream to get microphone input.  LÖVR automatically
  creates an internal stream for capture devices and exposes it via `lovr.audio.getStream`, making
  it easier to get microphone input.

Controller Models
---

`lovr.headset.newModel` can load animated controller models now, using the new `XR_EXT_render_model`
OpenXR extension.

Microgestures
---

Quest added support for "microgestures" which are performed by swiping the thumb along the index
finger.  LÖVR exposes this as a virtual dpad.

HDR
---

LÖVR has experimental support for HDR displays now.  Set `t.graphics.hdr = true` in conf.lua to
request an HDR10 window texture, and use `lovr.graphics.isHDR` to check if it was supported and
successfully enabled.

Currently, LÖVR doesn't do any automatic color space conversion for you -- you are expected to write
PQ-encoded Rec2020 colors to the window texture.  There are some new shader helpers like
`linearToPq` and `sRGBToRec2020` to help out with this.

Multithreading
---

This version adds a new coroutine-based task system in the `lovr.task` module.  Tasks make it easy
to run expensive work on background threads without blocking the main thread.  This is useful for
things like asset loading, GPU readbacks, physics updates, map generation, or any other
CPU-intensive logic.

Tasks share state with the main thread, and their code looks synchronous despite running work on
background threads.  This makes them much more ergonomic than managing `Thread` and `Channel`
objects.

Here's a simple example that loads a `Model` in the background and assigns it to the `model`
variable once it's ready (possibly several frames later):

    lovr.task.start(function()
      model = lovr.graphics.newModel('teapot.glb')
    end)

See the [Tasks](https://lovr.org/docs/Tasks) guide for a full explanation of how it works.

### Multithreaded Rendering

The graphics module is thread-safe now!  `Pass` objects can be recorded from any thread, and
multiple `Pass` objects can be recorded in parallel.  Also, graphics objects like `Texture`,
`Model`, and `Shader` can be created on any thread now.

### Internals

Additionally, several internal operations are multithreaded now:

- Shader compilation
- MSDF glyph rasterization
- Reverb simulation
- Texture loading for models

Model Improvements
---

There are a few important improvements to the `Model` API:

- `Pass:drawPart` is a nifty new function that draws a single part of a `Model`, allowing render
  states and shader uniforms to change for different parts of a model.
- Models no longer hold a reference to their `ModelData`, allowing the CPU memory for a model file
  to be released after the Model is created.
- LÖVR supports importing two sets of UVs now, making it possible to import models with lightmaps.

Luau
---

LÖVR supports [Luau](https://luau.org) as an additional Lua implementation, alongside PUC Lua and
LuaJIT.  Luau is mostly backwards compatible with Lua 5.1, but comes with some nice benefits like:

- Syntax extensions, like compound assignment operators (`+=`)
- Type checking
- Builtin vector type
- Native code generation

See the [Luau guide](https://lovr.org/docs/Luau) for the full details about Luau support in LÖVR.

Vectors
---

LÖVR's vector API was a frequent pain point.  The mutating API and permanent/temporary split were
confusing, and the C method call overhead prevented JIT compilation.  The vector API was reworked in
v0.19.0 to solve these issues, with the following changes:

- No more mutating API.  Instead, vectors are immutable.  Functions that return vectors always
  return a new vector instead of modifying their input vector.
- No more permanent/temporary split.  Vectors are always permanent now.
- Vectors are tables instead of userdata now, so their code can be JIT compiled and C method call
  overhead is eliminated.  As a bonus, functions that accept vectors also accept any vector-shaped
  table.
- Compatibility with Luau's `vector` type.

There were some unavoidable breaking changes here.  To ease porting, [this gist](https://gist.github.com/bjornbytes/62a54c6e200bd111068c5626433a7ad5)
implements the old vector API using tables.

Error Screen
---

The ever-present error screen has been upgraded into a fancy new stack trace explorer.  It supports
viewing source code and inspecting variables for entries in the stack trace.

Other Stuff
---

- It's easier to set custom camera projections with `Pass:setProjection` now.  For example,
  `Pass:setProjection('orthographic')` sets a 2D projection instead of requiring a matrix.
- `Pass:getViewRay` makes it easier to get a ray for a given canvas pixel, which is really useful
  for mouse picking.
- The headset simulator logic has been moved to Lua and can be overridden using the `lovr.simulate`
  callback!
- The GPU allocator is much smarter now, eliminating some situations where LÖVR would run out of
  VRAM due to fragmentation.  Small LÖVR projects also use less VRAM now.
- There are a few improvements to the desktop window API:
  - The window is centered by default
  - Add `lovr.system.setWindowFullscreen` to toggle fullscreen
  - Add `lovr.system.setMouseMode` to toggle mouse grab
